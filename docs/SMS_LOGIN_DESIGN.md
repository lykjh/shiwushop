# 手机验证码登录：开发前需求与边界设计

状态：设计稿，尚未实现或验收。基于 2026-10-30 的 `shiwushop` 工作区。本文只覆盖会员手机号绑定与验证码登录；现有用户名密码登录继续使用。

## 1. 目标与用户流程

1. 已有账号的用户先用密码登录，在账号设置中验证**当前密码和新手机号收到的绑定验证码**，将手机号绑定到该账号。一个手机号只对应一个账号。
2. 已绑定的用户可以请求登录验证码，提交手机号和验证码后获得与密码登录相同的 `MALLSESSION` 会话。`GET /users/me`、退出、改密及账号停用规则对两种登录方式一致。
3. 手机号未绑定、账号停用、验证码错误或过期时，不建立登录态。发送接口对外给出统一提示，避免通过响应探测手机号是否已绑定。
4. 换绑手机号要求当前有效会话、当前密码和新手机号的绑定验证码；成功后提升账号鉴权版本，使旧会话失效。唯一约束阻止同一手机号绑定两个账号。

本期不做验证码自动注册、找回密码、手机号之外的通知短信，也不把收货地址里的联系电话当作登录手机号。未绑定手机的用户仍用用户名密码登录。

## 2. 接口契约

接口沿用项目的 `Result<T>` JSON 格式、HTTP 状态与 `X-CSRF-TOKEN`。发送、绑定和登录均为 `POST`，使用 JSON 请求体，不把手机号或验证码放入 URL 查询参数。

| 接口（拟定） | 身份要求 | 请求与结果 |
| --- | --- | --- |
| `POST /users/phone/bind/send` | 已登录 | 新手机号；通过额度检查后尝试发送绑定码，返回统一发送提示。 |
| `POST /users/phone/bind/confirm` | 已登录 | 当前密码、新手机号、绑定码；成功后保存绑定并撤销旧会话。 |
| `POST /users/sms/send` | 匿名 | 手机号；对外返回统一发送提示，内部只给满足登录条件的绑定号码发送。 |
| `POST /users/sms/login` | 匿名 | 手机号、登录码；成功返回现有 `LoginVO` 并设置 Session Cookie。 |

校验失败使用稳定业务错误与对应 HTTP 状态；额度耗尽用 `429` 和 `Retry-After`，Redis 或短信渠道不可用用 `503`。验证码校验失败只返回通用提示。请求体字段由 DTO 校验：国内手机号格式、6 位数字验证码和必要的当前密码。现有 Demo 的 `/sms/login/send`、`/sms/login/verify` 不作为正式契约。

## 3. 数据与身份边界

- **MySQL 是持久身份来源。** 扩展现有 `user_private`：保存手机号密文，以及用独立密钥计算的规范化手机号 HMAC 查询摘要；对摘要建唯一索引。查询摘要不使用普通 SHA-256，避免手机号号码空间被离线枚举。历史账号没有绑定记录时，先完成绑定再使用短信登录；不从收货地址推断绑定关系。
- **账号状态仍由 `user_accounts` 决定。** 验码成功后查询绑定的账号，核对 `ACTIVE` 和 `authVersion`；更换 Session ID，写入与密码登录相同的 `userId`、`authVersion`，返回 `LoginVO`。登录接口不直接创建用户或提升角色。
- **Redis 只保存短期挑战与额度。** 登录码和绑定码使用独立用途、独立键空间，保存带密钥的验证码校验值、到期时间及错误次数；键名使用手机号查询摘要，不使用明文号码。验证码有效 5 分钟，每份最多 5 次错误验证；正确码通过原子操作立即删除，两个并发提交最多成功一个。过期、换绑和耗尽次数后删除挑战。Redis 不可用时返回 `503`，不按成功处理。
- **凭证边界。** 密码、短信验证码、完整手机号、短信 AccessKey、Cookie 均不写业务日志；只记录请求 ID、动作、结果、耗时和脱敏的渠道错误码。手机号加密密钥与查询摘要密钥分别配置并保管，不提交仓库。手机号摘要密钥轮换需要单独的数据迁移方案。

## 4. 发送与防滥用规则

- 使用安全随机源生成 6 位验证码。验证码发送与账号绑定各有独立用途；一种用途的验证码不能提交给另一接口。
- 同一手机号发送间隔初值为 **60 秒**，每小时最多 **10 次**；同一验证码最多 **5 次错误验证**。这些数值放配置中，测试共享出口用户后调整。手机号维度保护短信成本，入口另设宽松的 IP 级容量保护；共享 IP 不作为账号身份，也不单独撤销别人的登录态。
- 发送额度与验证码尝试数在 Redis 内原子更新，保证并发请求不会超发或重复使用。新验证码只有在短信渠道确认接收后才进入可验证状态；渠道拒绝或明确失败时清除待发送挑战。渠道超时按未知结果处理，不激活验证码，向客户端返回可重试的服务错误。
- 发送接口响应不回显验证码。模拟发送仅在专用本地测试配置中启用；正式运行缺少短信配置时返回 `503`，不退化为写日志发送。上线前对发送量、失败率和费用设置监控阈值。

## 5. 组件职责与工具用途

| 组件／工具 | 具体用途 | 边界 |
| --- | --- | --- |
| Controller、DTO、Service | DTO 校验入参；Controller 包装统一响应；Service 编排绑定、发码、验码及建会话。 | 登录状态由账号服务决定，短信渠道响应不直接代表登录成功。 |
| MySQL、MyBatis | 持久化账号与手机号绑定；摘要唯一索引处理并发绑定冲突。 | 不存短信验证码，不以收货地址手机号作为登录绑定。 |
| Redis、Spring Session | 保存短期验证码挑战、发送额度、失败次数和现有登录 Session；用原子脚本消费验证码。 | 故障时失败关闭；挑战 TTL 到期自动清理。 |
| Spring Security CSRF | 保护发送、绑定和登录的写请求；客户端先通过现有 `/users/csrf` 获取令牌。 | 短信验证码不替代 CSRF，也不替代登录后的 Session 校验。 |
| 阿里云短信 SDK | 向已绑定号码发送登录短信，向待绑定号码发送绑定短信；检查渠道业务响应码。 | AccessKey、签名和模板从运行环境注入；SDK 调用设超时。 |
| RabbitMQ | **本期不接入登录验证码链路。** | 验证码短时有效，异步排队会增加“已排队／已发送／可验证”的状态与重试歧义；现有 MQ 继续用于物流，不承担登录成功判定。 |
| 日志与指标 | 记录发送请求数、渠道成功／失败、验证码校验结果、限流触发数、登录成功率与耗时。 | 只用请求 ID 串联流程，日志不含验证码、完整手机号或密钥。 |

## 6. 实施顺序与验收

1. 移除 Demo 的错误日志导入，恢复编译；先写手机号绑定和唯一查询的数据迁移、密钥配置与服务测试。
2. 实现发送额度、短信渠道适配和本地测试替身；明确渠道失败与 Redis 故障响应。
3. 实现验证码原子校验与消费、账号查询、状态检查和现有 Session 建立；接入统一接口响应和 CSRF。
4. 完成单元测试、Controller 切片测试、真实 MySQL＋Redis 集成测试；仅在隔离环境验证短信渠道配置。保留测试命令和日志后再发布。

验收用例：绑定与换绑唯一性；正确验证码登录后 `/users/me` 返回对应账号；错误、过期、跨用途、重放和并发提交被拒绝；停用账号及未绑定手机号不建立会话；改密和换绑后旧会话失效；共享 IP 下不同已绑定用户正常登录；额度、渠道失败、Redis 故障均返回预期状态。现有密码登录、注册、CSRF 和退出用例继续通过。

上线边界：正式运行须具备保护短信验证码与 Session Cookie 传输的入口；在此之前仅用于本地或受控测试环境。当前 Demo 编译失败、`verify()` 恒为 `false`，尚未达到本设计的任何登录验收项。
