# 日志与排障

## 日志位置与开关

- 默认写入 `./logs/shiwushop.log`，路径相对于应用工作目录；可用 `SHOP_LOG_FILE` 指定绝对路径。单文件 20 MB，最多保留 14 个历史文件，总量上限 1 GB。
- HTTP 请求日志默认开启。每条包含 `requestId`、`module`、HTTP 方法、路由模板、状态码和耗时。响应头 `X-Request-Id` 可用于定位同一请求。
- 方法追踪默认关闭。排障时设置 `SHOP_METHOD_LOG_ENABLED=true` 并重启应用；它记录 Spring 代理覆盖的公开方法、结果、异常类型和耗时，不记录参数或返回值。排障结束后关闭。
- 关键状态变化输出 `business module=... action=... entity=... entityId=... outcome=committed`；有数据库事务时仅在提交后输出。业务事件目前覆盖账号注册/登录/改密/退出、店铺与商品编辑、评价、订单创建/支付/取消、售后退款、物流和图片上传。
- 搜索与物流消息日志包含 `eventId`，用于串起 outbox 投递与消费。定时扫描汇总日志按原有任务开关输出。

日志不记录请求体、密码、Cookie、完整 URL 查询参数、收货地址或支付凭证。`entityId` 是内部数字 ID；公开日志前应按运行环境限制文件访问权限。

## 排查顺序

1. 从客户端响应头取 `X-Request-Id`，在日志中搜索 `requestId=...`，查看路由、状态码和耗时。
2. 若请求返回 5xx，继续查同一 `requestId` 的异常日志；若是业务状态问题，按 `entityId=...` 搜索成功提交的 `business` 事件。
3. 搜索、物流异步问题按 `eventId=...` 查投递、重试、消费；不能用 HTTP 的 `requestId` 跨越消息队列追踪。
4. 仍无法定位时，短时间开启方法追踪，按 `module=` 和 `method=` 看耗时和失败位置，随后关闭。

日志用于定位请求和状态转换；它不替代数据库审计记录，也不保证 JVM 异常退出前缓冲区里的最后一行已经落盘。
